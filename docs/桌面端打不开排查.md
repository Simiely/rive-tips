# 桌面端打不开排查

**TL;DR**

1. 双击 Rive「完全没反应」、进程不到 1 秒就退出：先查有没有上一轮留下的无窗口 `RiveEarlyAccess` 进程，它占着单实例锁。
2. 判据三条同时成立：`StartTime` 是很早以前、`CPU` 还在增长、`MainWindowHandle = 0`。结束它再启动即可（本轮实测 1.1 秒出窗）。
3. 每次启动必写 5 条 `rive_native` 事件（Native → D3D 设备 → renderer context）；Sentry `session.json` 的 `duration` 只有几微秒，表示进程初始化后立刻结束。
4. **不要直接运行 `WindowsApps` 下的 exe 做启动测试**：没有包身份时会干净退出（实测 0.32 秒），会误判成「应用坏了」。
5. 本轮只证实「僵尸进程占单实例锁」这一条；它为什么会在运行 13.5 秒后变成无窗口进程，未查明。

> 更新时间：2026-11-13 ｜ 已验证：Rive 桌面版 Early Access `rive_native@0.9.639+6628`（Windows 11 `10.0.26100`，MSIX）

## 一、先把三种「打不开」分开

| 现象 | 方向 | 去哪 |
|---|---|---|
| 双击后没有窗口，进程 1 秒内退出 | 单实例锁 / 残留进程 | 本篇 |
| 有窗口但一直 `Compiling` | 客户端编译 / 环境 | [桌面端编译卡死排查](桌面端编译卡死排查.md) |
| 系统里完全没有进程被创建 | 快捷方式 / 包注册 / 激活 | 查 `Get-AppxPackage` 与 `AppXDeploymentServer/Operational` |

先看任务管理器里有没有 `Rive Early Access` 进程：**有进程但没窗口** → 大概率是僵尸；**没进程** → 去查激活层，不要按本篇处理。

## 二、本轮实测时间线

| 时间 | 现象 | 证据 |
|---|---|---|
| 11/12 19:31 | 启动 13.5 秒后 Sentry 写了一条 `fatal`；窗口消失，但进程一直活着 | `session.json` 的 `duration = 13.575`；11/13 检查时 `MainWindowHandle = 0`、`CPU` 累计 389 秒 |
| 11/13 16:41–16:47 | 共 9 次启动尝试，每次都创建了进程，0.3–0.7 秒退出 | 每次只写 5 条 `rive_native` 事件；Sentry `duration` 为 `4e-06`–`9e-06` |
| 11/13 17:06 | 结束残留进程后，用开始菜单激活 | 1.1 秒出现窗口；15 秒后仍有窗口句柄且响应正常 |

结论：应用和包都没坏，是**旧进程没退干净**。

## 三、判据与命令

```powershell
Get-Process RiveEarlyAccess -ErrorAction SilentlyContinue |
  Select-Object Id, StartTime, CPU, Responding, MainWindowHandle, MainWindowTitle
```

| 读到的结果 | 含义 |
|---|---|
| `MainWindowHandle = 0`，`StartTime` 是很早以前，`CPU` 很大 | 僵尸：窗口已销毁，进程没退，占着单实例锁 |
| 没有进程 | 不是单实例锁，转去查激活 / 包注册 |
| 有窗口句柄 | 已经正常启动，转去查「卡不卡」 |

## 四、修复

```powershell
Get-Process RiveEarlyAccess -ErrorAction SilentlyContinue | Stop-Process -Force
```

然后从开始菜单启动。注意：无窗口进程里即使有未保存内容也取不回来，执行前先确认没有正在保存的任务。

复发时同样处理。如果频繁出现，再考虑升级或重装；重装的归因边界见[桌面端编译卡死排查](桌面端编译卡死排查.md)§六。

## 五、取证链（不依赖 WER）

- **事件日志**：`Application` → Provider `rive_native`。每次启动固定 5 条：`RiveNativePlugin::RiveNativePlugin` → 选 D3D 设备 → `Got D3D device` → `Making renderer context` → `Made renderer context`。有这 5 条 = 已进原生层，不是快捷方式问题。
- **Sentry**：`%LOCALAPPDATA%\Packages\<包族名>\LocalCache\Local\Rive\sentry-native\<uuid>.run\`。`session.json` 的 `duration` 为 `4e-06` / `9e-06` = 进程几乎立刻结束；`__sentry-event` 只有 `level=fatal`，**没有堆栈**。
- **包升级**：`Microsoft-Windows-AppXDeploymentServer/Operational` 按包族名搜，可看到自动升级前后的版本（本轮 11/11 15:24 从 `1.9.560.6549` → `1.9.639.6628`）。
- **WER 无记录 ≠ 没崩**：干净退出不写 WER；本轮既没有 Application Error 1000，也没有 dump。

## 六、一个反直觉的坑：直接运行 exe

```powershell
# 错误做法：无包身份，0.32 秒后自行退出，stderr 无异常
& "C:\Program Files\WindowsApps\<包族名>\RiveEarlyAccess.exe"

# 正确做法：按开始菜单的方式激活
Start-Process explorer.exe -ArgumentList "shell:AppsFolder\<包族名>!riveeditor"
```

无包身份时应用会自行退出，日志里只有 Sentry / Flutter 初始化信息。**因此「直接跑 exe 也打不开」不能证明应用坏了。**

## 七、未验证线索（不计入结论）

- 11/12 那次运行 13.5 秒后为什么变成无窗口僵尸：Sentry 的 `fatal` 事件没有堆栈，未定位。
- 双显卡 / 虚拟显示器：Sentry 上下文里 GPU 适配器重复出现（NVIDIA ×4 + Intel ×1），本机另有 3 个虚拟显示驱动；未做「禁用虚拟显示器 / 强制高性能 GPU」的 A/B，不能算已证实原因。
- Early Access 与正式版差异：未单独验证。
