# 换素材后动画不生效：两类症状与排查

换掉一个带动画的素材（图标、辉光、车、按钮底图）之后，动画「没了」或「位置歪了」。
这两种现象根因完全不同，混在一起查会浪费很多时间。

## TL;DR

1. **先分两类**：**不跳**（动画根本没驱动这个对象）与 **跳但漂**（驱动对了，缩放锚点在错的点上）。
2. **不跳的第一嫌疑是「动画打错对象」**：新素材被加成旧节点的**兄弟**，而关键帧打在旧节点上。
   换素材时旧节点通常只是被 `opacity = 0` 藏起来，**没有删**，键还留在它身上。
3. **不要靠 reparent 去「继承」动画**：那个旧节点往往 `opacity = 0`，把新素材塞进去会**连它一起隐藏**。
4. **缩放锚点**：SVG / Image 实例的 `x/y` 是**左上角**，不是中心；而给一个位于 `(0,0)` 的**外层组**打缩放，
   是绕**画板原点**放大，内容会直接飞出画板。
5. **只改结构的操作，用「改前改后各截一张图、逐像素 diff 必须 = 0」来证明零位移** —— 这是把"我觉得没动"变成证据。

---

## 一、先分两类症状

| | 症状 A：不跳 | 症状 B：跳但漂 |
|---|---|---|
| 表现 | 素材静止，完全没有动画 | 有动画，但放大时往某个方向跑 / 位置整体偏了 |
| 根因 | 关键帧没作用在这个对象上 | 作用上了，但 `sx/sy` 的旋转中心不对 |
| 判据 | `queryKeyFrames` 里没有该对象的键 | 有该对象的键，但 `x/y` 不在几何中心 |
| 修法 | 给新对象自己打键（§二） | 挪锚点（§三） |

两类会**同时出现**：素材换完既没动画、又因为改了 `x/y` 把位置搞偏。所以先判 A 再判 B。

---

## 二、症状 A：不跳

### 2.1 三步排查

```python
# 1) 这条时间线上，键到底打在谁身上？
r = R.call('animation_editor', {'command':'queryKeyFrames','data':{'animationIds':['9-10687']}})
# 看每条的 objectId

# 2) 新素材的真实父级是谁？和上面那些 objectId 是不是同一条链？
h = R.call('get_artboard_hierarchy', {'artboardId':'9-5374'})
# 关注 objects[].children，从新素材 id 往上找祖先

# 3) 冒烟：状态机是不是真的在跑这条时间线？
R.call_text('animation_editor', {'command':'simulateStateMachine','data':{'stateMachineId':'9-10713'}})
```

**实测样本**（2026-11-13，充电桌面 003 图标）：

```
关键帧打在：9-5376  「充电图标」(旧矢量图标)，sx/sy 与两个填充的 color
实际结构：
  9-5375 「充电图标_缓入缓出」        ← 外层组，位于 (0,0)
    ├─ 9-5376 「充电图标」           ← 键在这，但 opacity = 0（被藏起来了）
    └─ 15-43  「ICON_charge_006」    ← 新素材，是 9-5376 的【兄弟】
```

结论一句话：**动画在，只是驱动的是一个看不见的旧节点。**

> 这个结构不是意外，而是"换素材时为了保险把旧节点设成 `opacity=0` 隐藏、不删"的必然结果。
> 所以只要项目里还留着旧节点，换素材后就要主动怀疑这一条。

### 2.2 为什么不能 reparent 进旧节点

看上去最省事：把新素材拖进 `9-5376`，直接继承那组键。**不行**——`9-5376` 的 `opacity = 0`，
父级透明会连子级一起隐藏，新素材会一起消失。

同理，也不要指望"把旧节点 `opacity` 改回 100、把旧形状自己藏起来"：那是两个改动，
且旧形状和新素材形状几乎重合，容易出现双份叠影（半透明边缘会露馅）。

### 2.3 修法：给新对象自己打键

复用**同一条时间线**，只给新对象补键，帧位/数值/插值全部照抄参考：

```python
add = []
for f, v in [(0, 100.0), (12, 125.0), (72, 100.0), (143, 100.0)]:
    add.append({'objectId':'15-43','propertyKey':16,'frame':f,'value':v,'interpolationType':'cubic'})  # sx
    add.append({'objectId':'15-43','propertyKey':17,'frame':f,'value':v,'interpolationType':'cubic'})  # sy
for f, c in [(0,'#ff00a86b'), (12,'#ff00a86b'), (72,'#80ffffff'), (143,'#80ffffff')]:
    add.append({'objectId':'15-79','propertyKey':37,'frame':f,'value':c,'interpolationType':'cubic'})  # color
R.call_text('animation_editor', {'command':'modifyKeyFrames','data':{'animationId':'9-10687','add':add}})
```

要点：

- **颜色动画只对矢量填充有效**。路径是 `Node → Shape → Path + Fill → SolidColor`，键打在 **SolidColor** 上（键 `37`）。
  如果素材是 Image / SVG 位图实例，就没有可关键帧的填充色，只能另加覆盖形状。
- 旧节点上那几组失效键**可以留着**（它不可见，无害），也可以清；清之前先确认旧节点确实不参与任何可见绘制。
- 时间线本身不用重建，`loop` / 时长通常已经是对的（本例 144 帧、`loop=1`）。

## 三、症状 B：跳但漂

### 3.1 三种错法

| 错法 | 后果 |
|---|---|
| 直接给 SVG/Image 实例打缩放 | 它的 `x/y` 是**左上角**，放大时向右下长，中心偏移 `尺寸 ×(倍率-1)/2` |
| 给外层组（位于 `(0,0)`）打缩放 | 绕**画板原点**放大，内容飞到画板右下角外 |
| 只改 `x/y` 补偿，不改子节点 | 位置对了，但缩放中心还是偏的，且每帧位移量随倍率变 |

### 3.2 正解：把节点原点放到几何视觉中心

不改父子关系，只做两件事：

1. 把**被缩放的节点**挪到素材的几何视觉中心；
2. 把它的**直接子节点**反向平移同样的量，抵消掉，使世界坐标不变。

实测（003 图标，58×58 的 SVG 实例）：

| 对象 | 改前 | 改后 |
|---|---|---|
| `15-43`（被缩放节点） | `(2199.04, 1141)` | **`(2228.02, 1170)`** = 几何中心 |
| `15-45`（直接子节点） | `(28.955, 29)` | **`(-0.025, 0)`** |
| 子节点世界坐标 | `2227.9951` | `2227.9951`（不变） |

```python
R.call_text('set_property_values', {'propertyValues':{
  '15-43': {'13': 2228.02, '14': 1170.0},   # 13=x, 14=y
  '15-45': {'13': -0.025, '14': 0.0},
}})
```

### 3.3 怎么算「几何视觉中心」

不要目测，**读顶点求包围盒**：

```python
verts = ['15-%d' % i for i in range(47, 62)] + ['15-%d' % i for i in range(63, 79)]
r = R.call_text('query_property_values', {'propertyKeys': {v: [24, 25] for v in verts}})  # 24=x, 25=y
```

实测该图标：`x ∈ [-28.955, 29.005]`、`y ∈ [-29, 29]` → 尺寸 **57.96 × 58**，
包围盒中心相对 `15-45` 偏 **(0.025, 0)**。

于是：

```
视觉中心(世界) = 节点x/y + 子节点x/y + bbox中心偏移
               = 2199.04 + 28.955 + 0.025 = 2228.02
               = 1141    + 29     + 0     = 1170
```

再反解子节点偏移，使 `子节点x/y + bbox中心偏移 = 0`：

```
子节点.x = -0.025   子节点.y = -0
```

**注意**：Image 实例没有顶点可读，用 `computedwidth / computedheight`（键 `810` / `811`）反推显示尺寸，
或直接用素材的原始宽高 × 缩放。若素材有透明留白，包围盒 ≠ 视觉重心，宁可偏一点点也不要偏到留白中心。

## 四、可复制流程

```
1. queryKeyFrames      → 确认键打在哪个 objectId（是不是旧节点）
2. get_artboard_hierarchy → 确认新素材的父级，判断是「兄弟」还是「子」
3. 若关键帧对象 ≠ 新素材祖先链 → 症状 A：确认旧节点 opacity=0，走「给新对象打键」
4. 若需要缩放 → 症状 B：读顶点求 bbox 中心，挪节点 + 反向补偿子节点
5. 打键（sx/sy + 颜色，帧位照抄参考）
6. 回读 queryKeyFrames + query_property_values 确认
7. capture 改前/改后逐像素 diff = 0（只改结构时）
8. simulateStateMachine 确认状态机在跑这条时间线
9. 编辑器播放肉眼确认
```

## 五、零位移证明

只改结构（锚点 / 父子 / 坐标）时，改完必须证明**画面一个像素没动**：

```python
import base64, numpy as np
from PIL import Image

a = R.call('capture_artboard', {'artboardId':'9-5374','longEdge':1536})
open('before.png','wb').write(base64.b64decode(a['result']['content'][1]['data']))
# ...改...
b = R.call('capture_artboard', {'artboardId':'9-5374','longEdge':1536})
open('after.png','wb').write(base64.b64decode(b['result']['content'][1]['data']))

d = np.abs(np.asarray(Image.open('before.png'), np.int16) -
           np.asarray(Image.open('after.png'),  np.int16))
print('max diff =', d.max())     # 期望 0
```

本例实测 **max diff = 0**（1536×837 全图）。

前提：**截图取的是静止帧**（第 0 帧 `sx=100`、颜色未变），否则动画相位不同会误判。
`capture_artboard` 不执行脚本，所以脚本绘制的内容不会干扰这个对比——这里反而是优点。

## 六、注意事项

| 现象 | 原因 | 处理 |
|---|---|---|
| 新素材完全不跳 | 键打在旧节点（`opacity=0`）上 | 给新对象补键（§二） |
| 新素材也不见了 | 被 reparent 进了 `opacity=0` 的旧节点 | 挪回外层组，改走"自己打键" |
| 放大时往右下跑 | 实例 `x/y` 是左上角 | 原点移到几何中心（§三） |
| 放大时飞出画板 | 给 `(0,0)` 的外层组打了缩放 | 缩放打在素材自身节点上 |
| 颜色不跟着变 | 素材是位图 / 实例化 SVG，没有可关键帧的填充 | 换矢量素材，或叠一层覆盖形状做颜色 |
| `capture` 前后对比不一致 | 截图取到了不同动画相位 | 保证对比点在静止帧（第 0 帧） |
| 补完键还是不跳 | 时间线没在状态机里播放 | `simulateStateMachine` 看 `finalStates` |

---

## 七、验收

1. `queryKeyFrames` 里**新对象**的 `sx/sy/color` 键齐全，帧位与数值和参考一致；
2. `query_property_values` 回读：子节点世界坐标与改前一致；
3. 只改结构时 `capture` 改前/改后 **max diff = 0**；
4. `simulateStateMachine` 走 `Entry → 目标 Timeline`，`settled` 前 `framesAdvanced > 0`；
5. 编辑器播放：素材在原位跳动、颜色按预期变化，与参考文件肉眼一致。
